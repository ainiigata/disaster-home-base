# 家族共有を有効にする(Firebaseセットアップ手順)

このアプリは、初期状態では家族との共有機能がオフになっています(家族カード画面を開くと「共有機能は未設定です」と表示されます)。それ以外の全機能(備蓄・持ち出し品・保管場所・手順の確認など)は、この設定をしなくてもこの端末の中だけで問題なく使えます。

共有をオンにすると、合言葉(パスフレーズ)を知っている家族の端末どうしで、家族カード・持ち出し品・保険メモなどの内容が自動的に同じ内容になります。この文書は、そのために必要な「Firebase」という無料の外部サービスの設定を、画面の操作ごとに説明します。

## お金の話を先に

**この手順で使うのはFirebaseの無料プラン「Sparkプラン」だけです。クレジットカードの登録は不要で、登録しなければ課金は物理的に発生しません。**

- Sparkプランはクレジットカードなしで使い始められます。カード情報を一切入力しないでください。
- 途中でFirebaseの画面が「Blazeプランへのアップグレード」を勧めてくることがあります。**その案内は無視して、アップグレードしないまま進めてください。** 具体的にどの画面で出るかは、該当の手順の中で改めて注記します。
- 無料枠は Firestore(このアプリが使うデータベース)で 1日あたり読み取り5万回・書き込み2万回・保存容量1GB です。家族4人が毎日アプリを開いて備蓄をチェックする程度の使い方では、この枠の一部さえ使い切りません。目安として、家族4人が1日に何十回もアプリを開閉しても、読み取り回数は数百回程度にしかならず、5万回には遠く及びません。
- 万一(通常の使い方ではまず起こりませんが)無料枠を超えることがあっても、**課金はされません。** 起こることは「その日の同期が一時的に止まる」だけです。アプリ自体は端末に保存されているデータでそのまま動き続け、日付が変わって枠がリセットされれば同期も自動的に再開します。

この前提を踏まえた上で、以下の手順を進めてください。

## 手順の全体像

1. Firebaseプロジェクトを無料で作成する
2. 匿名認証を有効にする
3. Cloud Firestore(データベース)を作成する
4. セキュリティルールを貼り付ける
5. アプリの設定値を `js/firebase-config.js` に貼る
6. 動作確認する

所要時間はおおよそ15〜20分です。途中で止めても、続きから再開できます(Firebaseプロジェクトは作成した時点で保存されています)。

---

## 1. Firebaseプロジェクトを作成する

1. ブラウザで https://console.firebase.google.com を開きます。Googleアカウントでのログインを求められたら、普段使っているGoogleアカウントでログインしてください。
2. 「プロジェクトを追加」または「Create a project」をクリックします。
3. プロジェクト名を入力します(例: 「わが家の防災」など、何でも構いません)。この名前は他の人には見えません。
4. 「続行」で次に進みます。**Google アナリティクスの設定画面が出た場合は、オフのままで構いません**(この機能は無料枠内ですが、家族共有には不要なので有効にする必要はありません)。
5. 「プロジェクトを作成」をクリックし、作成が終わるまで待ちます(数十秒程度)。「続行」でプロジェクトのダッシュボードに入ります。

**確認:** プロジェクトのダッシュボード画面(左上にプロジェクト名、中央に「アプリを追加してFirebaseの利用を開始しましょう」といったカードが並ぶ画面)が表示されていれば成功です。

この時点ではまだ料金プランの選択を求められません。プランの表示が出るのは主に手順3(Firestore作成)以降です。そこで改めて注意します。

---

## 2. 匿名認証を有効にする

このアプリは、名前やメールアドレスでのログインを一切使いません。家族であることの確認は「合言葉」だけで行い、Firebase側では「誰かがこのアプリを開いている」ことだけを匿名で確認します(この確認をしないと、次の手順で設定するセキュリティルールがデータへのアクセスを拒否する仕組みになっているため、この手順は省略できません)。

1. 左側のメニューから「Authentication(または「構築」→「Authentication」)」を選び、「始める」をクリックします。
2. 上部タブの「Sign-in method(ログイン方法)」を開きます。
3. 一覧の中から「匿名」を探してクリックします。
4. 右上のスイッチ(トグル)を有効にし、「保存」をクリックします。

**確認:** 「Sign-in method」の一覧で「匿名」の状態が「有効」になっていれば成功です。メールやGoogleログインなど、他の項目は触らずそのまま(無効)で構いません。

---

## 3. Cloud Firestore(データベース)を作成する

Firestoreは、家族カードや備蓄リストのデータを保存する場所です。

1. 左側のメニューから「Firestore Database(または「構築」→「Firestore Database」)」を選びます。
2. 「データベースの作成」をクリックします。
3. ロケーション(保存先のリージョン)を選ぶ画面が出ます。**`asia-northeast1`(東京)を選んでください。** 一度決めると後から変更できないため、ここは確実に選んでください。
4. モードの選択で「本番環境モード(production mode)」を選びます。「テストモード」は選ばないでください(テストモードは30日で誰でも読み書きできる期限付きの設定で、次の手順で貼るセキュリティルールと前提が食い違います)。
5. 「有効にする」または「作成」をクリックし、作成が終わるまで待ちます。

**この画面またはこの前後で、利用プランの確認や「お支払い方法の追加」を促す表示が出ることがあります。** Firestoreの作成自体は無料のSparkプランで可能です。**クレジットカードの登録や有料プラン(Blaze)へのアップグレードを求める画面が出た場合は、それを選ばずに閉じるか「後で」を選んでください。** カード情報の入力欄には何も入力しないでください。

**確認:** Firestoreのデータベース画面(まだデータが1件もない、空の「データ」タブ)が表示されていれば成功です。

---

## 4. セキュリティルールを貼り付ける

セキュリティルールは「誰が、何を読み書きできるか」を決める設定です。ここを飛ばす、または誤って緩い設定のまま公開すると、手順5で貼る設定値が公開情報である(後述)ため、**世界中の誰でもこのデータベースを読み書きできてしまいます。** この手順は省略できません。

1. Firestoreの画面上部にある「ルール(Rules)」タブを開きます。
2. 表示されているルールの内容をすべて選択して削除し、代わりに以下をそのまま貼り付けます(1文字も変えないでください)。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /households/{hid}/{doc=**} {
      allow read, delete: if request.auth != null && hid.size() == 64;
      allow create, update: if request.auth != null && hid.size() == 64
        && request.resource.data.size() < 40;
    }
  }
}
```

3. 「公開(Publish)」をクリックします。

### このルールが何をしているか

- `request.auth != null` — サインインしていない相手(手順2の匿名認証すら通っていない相手)からのアクセスは、読み書きどちらも拒否します。匿名認証も「サインイン」の一種として扱われるため、アプリを開いた端末は通れますが、ブラウザで直接データベースのURLを叩くような第三者は通れません。
- `hid.size() == 64` — `households` の下のIDが、ちょうど64文字であることを要求します。このアプリの合言葉は、内部で64桁の16進数(0〜9とa〜fの組み合わせ)の世帯IDに変換されてから使われます。桁数が合わないアクセスは拒否されるため、適当な短い文字列を世帯IDのつもりで送ってもデータには触れません。
- `request.resource.data.size() < 40` — 1回の書き込みで送れるデータの項目数に上限を設けています。アプリの通常の使い方(備蓄1件の追加、家族カード1件の編集など)はこの範囲に収まりますが、想定外に巨大なデータを一度に送りつけるような書き込みは拒否されます。
- `match /households/{hid}/{doc=**}` の外側、つまり `households` 以外のコレクションには、このルールは一切アクセスを許可していません。デフォルトで全拒否なので、書いていない範囲は自動的に閉じています。

まとめると、「合言葉から導かれた64桁の世帯IDを知っていて、かつ(匿名でも)サインイン済みの相手だけが、その世帯のデータだけを読み書きできる」というルールです。**この時点で、データの安全性は完全に「合言葉を誰が知っているか」に懸かっています。** 手順6の最後で改めて注意します。

**確認:** 「ルール」タブの上部に「公開済み」や公開日時が表示されていれば成功です。

---

## 5. アプリの設定値を貼る

1. 画面左上の歯車アイコン(プロジェクトの設定)→「プロジェクトの設定」を開きます。
2. 下にスクロールして「マイアプリ」の欄を探し、「</>」(ウェブ)のアイコンをクリックしてウェブアプリを追加します。
3. アプリのニックネームを入力します(何でも構いません、例: 「防災アプリ」)。「Firebase Hosting」のチェックボックスが出ても**チェックしないでください**(このアプリはHostingを使わず、既存の公開方法をそのまま使います)。
4. 「アプリを登録」をクリックすると、`firebaseConfig` という設定値が画面に表示されます。次のような形です。

```js
const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "xxxxx.firebaseapp.com",
  projectId: "xxxxx",
  storageBucket: "xxxxx.appspot.com",
  messagingSenderId: "...",
  appId: "..."
};
```

5. この6つの値を、このアプリのファイル `js/firebase-config.js` を開いて書き換えます。ファイルの最後にある

```js
export const firebaseConfig = null;
```

という行を、次のように書き換えます(値は自分のプロジェクトで表示されたものを使ってください)。

```js
export const firebaseConfig = {
  apiKey: "...",
  authDomain: "....firebaseapp.com",
  projectId: "...",
  storageBucket: "....appspot.com",
  messagingSenderId: "...",
  appId: "..."
};
```

6. ファイルを保存します。

### この値は「秘密」ではありません

`firebaseConfig` に入っている値(apiKeyなど)は、パスワードやAPIキーのような秘密情報ではなく、**「このアプリがどのFirebaseプロジェクトと話すか」を示す公開の識別子**です。Firebaseのウェブアプリは、ブラウザで動く以上、この値を必ず利用者全員に配ることになる(ブラウザの開発者ツールで誰でも見える)ため、隠す設計にはなっていません。コードに書いたままコミットしても問題なく、隠そうと苦労する必要はありません。

その代わり、**アクセス制御は手順4で貼ったセキュリティルールだけが担っています。** 設定値そのものは誰でも入手できる前提だからこそ、ルールの設定を飛ばしてはいけない、ということです。

---

## 6. 動作確認する

1. アプリを開き、「家族カード」画面に移動します。「共有機能は未設定です」という表示が消えていれば、設定値の読み込みまでは成功しています。
2. 「家族グループを作る」をクリックし、表示された合言葉をメモします(例: 「さくら・つばめ・ひかり・やま・4172」のような形です)。
3. 別の端末(家族のスマートフォンなど)で同じアプリを開き、「合言葉で参加」からその合言葉を入力します。
4. しばらく待って、最初の端末で入力した内容(家族カードの情報など)が2台目にも表示されれば成功です。

### 何も反映されないとき

- **手順2(匿名認証)が有効になっているか**をもう一度確認してください。Authentication → Sign-in method → 匿名 が「有効」になっていないと、この画面はずっと「接続中…」のまま止まります。
- **手順4のセキュリティルールが「公開済み」になっているか**を確認してください。ルールを貼り付けただけで「公開」を押し忘れていると、反映されません。
- それでも直らない場合は、`js/firebase-config.js` に貼った値がプロジェクト設定の画面に表示されているものと一致しているか(コピーミス・余分な引用符やカンマがないか)を見直してください。

### 合言葉の扱いについて、最後にもう一度

合言葉は、この家族グループのデータへの実質的な「鍵」です。手順4のルールが確認しているのは「64桁の世帯IDを知っているか」だけなので、**合言葉さえ知っていれば、家族以外の誰でもその世帯のデータ(避難先の集合場所、家族の持病や配慮事項なども含む)を読み書きできてしまいます。** 合言葉は家族以外には伝えないでください。誰かに誤って伝えてしまった場合は、家族カード画面の「共有をやめる」から一度共有を停止し、「家族グループを作る」から新しい合言葉で作り直してください(この端末に保存されているデータ自体は消えません)。
