# 防災ホームベース フルリニューアル 設計書

- 日付: 2026-08-22
- 対象: `008-disaster-home-base`(現在地で開発を継続)
- ステータス: ユーザー承認済みの設計方針を文書化したもの

## 1. 目的

「このアプリの通りに行動すれば災害が怖くなくなる」を実現する。具体的には:

1. 平時: 何をどれだけ備えればよいかをアプリが自動で示し、毎日「今日やる1つ」を提案する
2. 直前〜発生時: 災害を選ぶと段階別の行動手順が2タップ以内で表示される(オフラインでも)
3. 家族: 備え・集合場所・配慮事項を家族全員の端末で共有・同期する

## 2. 絶対制約(ユーザー指示)

- **有料サービスは一切使わない**。Firebaseは無料Sparkプランに固定し、クレジットカードを登録しない(=課金が物理的に発生しない)。Blazeプランへのアップグレード、Cloud Functions(Blaze必須)、有料API、従量課金サービスはすべて使用しない
- 無料枠(Firestore: 読取5万回/日・書込2万回/日・保存1GB)を超えた場合は同期が一時停止するだけで、アプリは端末内データで動作を続ける
- 実名・住所・証券番号全文・生年月日を保存しない方針は継続する
- シークレットをコードに直書きしない。なおFirebase Webアプリ設定(apiKey等)は公開識別子でありシークレットではない(アクセス制御はFirestoreセキュリティルールが担う)

## 3. 全体アーキテクチャ

### 3.1 構成

- **ビルド不要の静的サイト**(ES Modules)。GitHub Pagesで公開可能な構成を維持
- **PWA化**: `manifest.webmanifest` + Service Worker(`sw.js`)で「ホーム画面に追加」と完全オフライン起動に対応。Firebase SDK(CDN ESM)もService Workerでキャッシュする
- 現在の「全行1行」コードは廃棄し、責務別にファイル分割して書き直す

### 3.2 ファイル構成

```
index.html

sw.js
icons/                  … PWAアイコン(SVGから生成した192/512px PNG)
js/

  state.js              … 状態ストア・localStorage永続化・v1→v2移行
```

### 3.3 データの流れ(オフライン第一)

- **共有OFF(初期状態)**: localStorage(`a008.disaster-home-base.v2`)のみ。外部通信なし
- **共有ON**: 世帯データ(備蓄・保管場所・家族カード・保険)はFirestoreが正本になり、Firestoreのオフラインキャッシュで電波なしでも読み書きできる。UI状態・緊急チェック・お気に入りは端末ローカルのまま。localStorageには世帯データの最新スナップショットも書き、Firebase障害時の閲覧と共有解除時の引き継ぎに使う
- Firebase未設定(config未記入)でもアプリ全体が動作し、共有画面だけ「未設定」案内を出す

## 4. データモデル v2

- `schemaVersion: 2`
- 世帯データ(共有対象): `supplies` `locations` `familyMembers` `insurance` `household`(人数構成・備蓄目標日数・緊急連絡メモ)
- 端末データ(共有しない): `mode` `selectedHazard` `emergencyCheckedIds` `favoriteProcedureIds` `ui` `sync`(参加状態・世帯ID)
- `Supply` に追加: `recommendedKey`(推奨品目との紐付け。nullなら手動追加品)
- 全世帯エンティティに `updatedAt`(epoch ms)を持たせ、同期の競合解決に使う
- **移行**: 起動時にv1キーを検出したら安全に正規化してv2へ変換し、v1キーは残す(ロールバック保険)。移行済みフラグで二重移行を防ぐ

## 5. 家族共有(Firebase・合言葉方式)

### 5.1 仕組み

1. 「家族グループを作る」→ アプリが**合言葉を自動生成**: ひらがな単語リスト(512語)から4語 + 4桁数字(例: `さくら・つばめ・ひかり・やま・4172`)。エントロピー約49ビットで推測は実用上不可能。ユーザー任意の合言葉は推測されやすいため採用しない
2. 世帯ID = SHA-256(合言葉)。合言葉を知る端末だけが同じFirestoreパスに到達できる(ケイパビリティ方式)
3. 家族は合言葉を入力して参加。参加時に既存ローカルデータとの統合方法を選ぶ(「世帯データに合流(自分のデータを追加)」または「世帯データで置き換え」)
4. 合言葉はいつでも共有画面で再表示できる(端末に保存)。「共有をやめる」で端末をローカル専用に戻せる

### 5.2 Firestore構造とルール

```
households/{householdId}/
  supplies/{id}     … 1品目1ドキュメント
  locations/{id}
  members/{id}      … 家族カード
  shared/meta       … 作成日時・スキーマ版
  shared/insurance
  shared/household  … 人数構成・備蓄目標日数・緊急連絡メモ
```

- 認証: **匿名認証**(メール・パスワード不要、無料)
- セキュリティルール: サインイン済み(匿名可)かつ `households/{householdId}` 配下のみ読み書き可。ドキュメントサイズ・フィールド型の検証ルールも入れる
- 同期: `onSnapshot` でリアルタイム受信。書き込みは品目単位で、`updatedAt` の新しい方を採用(last-write-wins)。オフライン中の変更はFirestoreの永続キャッシュが復帰時に自動送信

### 5.3 セットアップ

- ユーザーがFirebaseコンソールで無料プロジェクトを作成(クレカ登録なし)し、Webアプリ設定値を `js/firebase-config.js` に貼る手順書(`docs/firebase-setup.md`)を用意する。Firestoreルールも同手順書に全文掲載する
- この手順が完了するまでアプリは共有機能OFFの完全ローカルモードで動く

## 6. 災害11種 × 段階別手順

- 対象: **地震・津波・台風・豪雨・洪水・土砂災害・大雪・停電・断水・火災・猛暑**(新潟の生活で起こりうる災害を網羅)
- 各災害の手順は5段階: `prepare`(ふだんの備え)/ `alert`(警報・直前)/ `now`(発生時=緊急モードの中心)/ `after`(直後)/ `recover`(生活再建)
- 1災害あたり8〜12手順、全体で100件超。内閣府・消防庁・気象庁の公開防災指針をもとに一般的な行動として記述し、「自治体・気象庁など公的な指示を優先」の明記は全画面で継続
- 検索・災害フィルター・お気に入りは現行機能を引き継ぎ、段階フィルターを追加

## 7. 機能仕様

### 7.1 備蓄量の自動目安(新規)

- 世帯設定: 大人人数・子ども人数・備蓄目標日数(3日/7日)
- `stock-guide.js` のテーブル(例: 飲料水3L/人/日、主食3食/人/日、簡易トイレ5回/人/日、モバイル電源、常備薬 等 約15品目)から必要量を計算
- 台帳と突合して品目ごとに「充足/不足/未登録」を判定。「おすすめセットをまとめて台帳に追加」ボタンで一括登録できる

### 7.2 ローリングストック支援(新規)

- 期限が近い順の一覧(30日以内を強調)
- 「消費した」1タップ → 数量を減らし「買い足しリスト」へ自動追加。買い足しリストはチェックで消し込み

### 7.3 準備率の再設計

- 6カテゴリ: 水 / 食料 / 電源・照明 / 衛生・トイレ / 情報・書類 / 家族・連絡
- カテゴリごとに達成条件(推奨備蓄の充足率+家族カード・集合場所・保険確認など)を定義し、「できている/あと少し/未着手」の3段階で表示
- ホームに**「今日やる1つ」**を毎回提案(未達の中から優先度順。5分で終わる粒度の行動)

### 7.4 緊急モード強化

- 災害選択は11種のグリッド。選択後は `now` 手順のチェックリストを最優先で全画面表示、続けて `after`
- 持ち出し品・集合場所・家族の配慮事項・**緊急連絡メモ**(世帯設定)・**171災害用伝言ダイヤルの使い方**を1画面に大きく表示。すべてオフラインで閲覧可能
- チェック状態の保存・再読込復帰・災害変更時のリセット確認は現行仕様を引き継ぐ

### 7.5 見直しリマインド

- 9/1(防災の日)・3/11の前後2週間、ホームに点検バナーを表示(プッシュ通知はしない)。「点検した」で当該期間は非表示

## 8. デザイン刷新

- 実装時に frontend-design スキルを使用
- 平時: 深緑×紙色の信頼感あるトーンを洗練。カード・余白・タイポグラフィを再設計
- 緊急時: 高コントラスト(白地に赤/黒)・文字サイズ拡大・1カラム集中レイアウト。ナビを隠し「戻る」だけ残す
- 高齢の家族も想定した文字サイズ・44px以上のタップ領域。360px(スマホ)第一で768/1280pxに対応
- 動き軽減(prefers-reduced-motion)・キーボード操作・読み上げ対応は現行水準を維持

## 9. エラーハンドリング

- 保存失敗: 入力を保持して再試行(現行踏襲)
- 破損データ: 安全な既定値へ正規化して復旧通知(現行踏襲)
- 同期エラー: オフライン/無料枠超過/ルール拒否を区別して表示。いずれもローカル動作は継続し、共有画面に状態インジケーター(同期済み/待機中/オフライン/エラー)を出す
- 合言葉入力ミス: 存在しない世帯に参加した場合は空の世帯が見えるだけ(データ漏えいなし)。「家族の画面に何も出ない場合は合言葉を確認」の案内を表示

## 10. テスト計画

- 手動確認: 2ブラウザプロファイルで世帯共有の作成→参加→双方向反映→オフライン編集→復帰同期
- 表示確認: 360/768/1280px、緊急モード、PWAインストール、オフライン起動
