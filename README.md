# 防災ホームベース

備蓄、持ち出し品、保管場所、家族情報、災害別手順、保険情報が分散し、平時に見直せず、緊急時に「あれはどこ」「どうすればよい」が分からなくなる——それを一つの端末内アプリにまとめる防災アプリ。

- **11災害**(地震・津波・台風・豪雨・洪水・土砂災害・大雪・停電・断水・火災・猛暑)、**107件の段階別手順**(ふだんの備え/警報・直前/発生時/直後/生活再建。災害ごとに該当する段階のみ)
- **五つの画面**: ホーム(準備率6カテゴリ・今日やること)/準備台帳(持ち出し品・備蓄・入れ替え・保管場所・保険)/手順を探す/家族カード/緊急モード
- データは端末内 `localStorage` のみ。家族共有(Firebase)を設定しない限り、外部通信は一切発生しない
- PWA対応。ホーム画面に追加してオフラインで全機能を開ける

詳しい設計・データ構造・状態遷移は [APP.md](./APP.md) を参照してください。

## 起動方法

ES modules（`<script type="module">`）を使っているため `file://` では動きません。ローカルの静的Webサーバーで配信してください。

```sh
python3 -m http.server 8008
```

その後ブラウザで `http://localhost:8008/` を開きます。ポート番号は空いていればどれでも構いません。

## テストの実行

```sh
npm test
```

`node --test tests/*.test.js` を実行します（追加の依存パッケージなし）。

## 家族共有(任意)を有効にする

初期状態では家族カード画面の共有機能はオフで、それ以外の全機能は端末内だけで完結します。合言葉を知っている家族の端末どうしでデータを同期したい場合は、無料のFirebase「Sparkプラン」(クレジットカード登録不要・課金なし)を使って設定できます。手順は [docs/firebase-setup.md](./docs/firebase-setup.md) を参照してください。

## デプロイ時の注意(必読)

`sw.js` の先頭にあるキャッシュバージョンは、**デプロイのたびに必ず値を上げてください**。

```js
const CACHE = "dhb-v1";
```

上げ忘れると、既に一度アプリを開いたことがある利用者の端末では、Service Workerが古いバージョンのJSモジュールをキャッシュから配信し続け、コードを更新してもその利用者には新しい内容が一切届きません(この不具合は本プロジェクトで実際に長時間の原因調査を招いています)。デプロイ手順に組み込んで、`git commit` 前のチェックリストに加えることを推奨します。
